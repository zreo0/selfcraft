## 多端对话

- 模拟器实际通过原生客户端发送测试文本，Runtime 持久回复 `IOS_CHANNEL_OK`
- Web Cookie 与原生 Bearer 返回相同稳定实例身份
- 两个入口同时提交同一个 ID，历史仅有一条用户消息及一条回复
- CLI `RuntimeClient` 实时订阅收到最终快照；Web 历史接口取得相同完成结果
- iOS 无需手动刷新便显示 `MULTI_CLIENT_0225c95f` 的跨端输入和回复
- App 重建、重新启动后恢复连接及历史；服务器重启后继续使用同一实例身份

这验证了共享 Runtime、稳定提交 ID 和同一份历史的核心设计。它不替代所有真机断网、杀进程、后台恢复组合的回归。

## 真实语音

使用系统 Tingting 合成中文录音，转换为 16 kHz、单声道、16 bit PCM WAV，未采集环境麦克风。测试密钥仅保存于测试 Runtime 的 `config/secrets.json`。

- 实际时长：9.391125 秒
- 模型：`FunAudioLLM/SenseVoiceSmall`
- 真实转写请求耗时：40306 ms
- 文本：`这是一条语音识别测试，请知回复语音通道已收到，不要调用工具，也不要保存为长期记忆。`
- 存在误字：“请只回复”识别为“请知回复”
- 同 ID 再次转写返回已保存结果；两次对话提交仅生成一条语音消息
- 受鉴权保护的音频下载与上传原件逐字节一致
- iOS 实时出现 9 秒语音条和文字；点击可播放，Agent 完成回复

这是一次连通性与数据一致性验收。40.3 秒延迟偏高，不能据此宣称接近日常即时通讯体验；后续需要比较真实用户短录音、网络状况和不同供应商延迟。

## 历史滚动稳定性优化（2026-09-29）
