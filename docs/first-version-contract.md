# 最小首版的运行与升级约定

本约定描述代码实际支持的本地单用户版本。助理的判断质量仍需真实模型和长期使用验证；测试通过不等于可以完成任意任务。

## 实例与实现

- 一个数据目录只允许一个 Runtime 写入，CLI、Web 面对同一个助理
- 身份、关系、记忆、事项、技能、成果属于实例，代码更新不能用默认模板覆盖它们
- Topic 用于组织证据；Work 保存目标与责任；Job 是一次执行；Execution 保存模型步骤与工具结果；Session 是供模型使用的对话上下文
- 用户不管理 session。普通闲聊不强制创建 Work；持续行动、等待与承诺应进入 Work
- Supervisor、状态兼容检查、候选验收及其测试是 Runtime 不能通过演化工具修改的基础

## 持续事项

事项记录目标、完成条件、授权说明、来源、版本、进展、下一步与等待条件。

- `ready`：允许助理继续推进
- `running`：正在进行一次有界决策
- `waiting`：等待用户、绝对时间或关联 Job
- `completed`：助理已经记录结果与验收依据
- `blocked`：缺少条件、操作结果未知、模型失败或达到自动推进预算
- `cancelled`：取消继续推进；已发生的外部操作不会被撤销

`work_create`、`work_list`、`work_update` 供助理管理事项。后台只能推进当前事项，不能改写原目标或扩大记录的授权。授权文字用于决策约束，不是操作系统权限沙箱。

时间与 Job 状态由确定性扫描器检查，空闲时不调用模型。Job 终态只使事项重新就绪，由助理验收后决定完成、补做或等待。用户补充信息后，前台助理更新原事项；不对任意相似文本自动匹配事项。

每次工具执行前检查事项版本。版本变化后，旧执行不能继续调用工具；旧后台 Job 会被取消。已经启动的外部操作可能仍产生结果，因此版本变更不能被理解为撤销外部副作用。

单次事项接续最多运行两分钟，同一条件最多自动推进八轮；达到限制持久记录为 blocked，避免无人值守时持续消耗模型。前台单轮最多三分钟，单次图片分析最多两分钟，长任务应交给 Job，后台执行期间可以继续对话。前台输入仍按接收顺序处理，不保证打断模型时即时回复。

## 接收、执行与交付

前台输入先持久接收再执行。关闭浏览器停止观察，不代表取消已接收的工作。重启先恢复持久队列。自然语言取消通过更新原事项实现。

每个完整模型步骤保存响应检查点。工具调用前保存参数，工具返回后立即保存完整结果；较大结果沿用工作区成果文件。重启时：

- 尚未开始的输入继续执行
- 完成的步骤与已知工具结果复用，不重新执行原工具调用
- 已知工具结果但缺少模型步骤时，重建 assistant/tool 消息闭环
- 操作已开始但结果未保存时，暂停自动执行；助理可用 `execution_status` 查询证据并检查实际状态
- 不承诺任意外部操作 exactly-once；未知结果不能用重新运行来猜测

会话快照、原文和提交标识在同一个 SQLite 事务中更新。模型最终输出已保存但会话交付中断时，相同执行不会重复追加。事项结果与待投递通知在同一事务提交；通知写入后确认投递，已读通知仍保留去重依据。

旧 `context.json`、`transcript.jsonl` 和通知 JSONL 只导入一次并原样保留。新数据以各目录中的 SQLite 为准，不再持续更新旧 JSONL。上下文压缩不删除 SQLite 中的原始消息。

## 自我成长

Reflection 仍只产生候选。空闲扫描把有重复证据且置信度足够的候选转成持久事项，每个候选只创建一次，不因重启反复开始。

助理先核实问题，再选择修订技能或提出 Runtime 候选。`growth_resolve` 要求留下验证依据。Runtime 改进必须关联成长候选，并在 Supervisor 标记相应发布稳定后才能接受候选；暂存后应等待重启，再读取 `runtime_release` 检查结果。

稳定表示候选通过当前检查及启动观察，不表示已经证明长期效果。后续新证据仍可形成修正事项。首版没有自动发现上游版本的监视器，也不保证自动解决任意代码冲突；上游变更可以作为普通改进事项输入，通过相同的候选路径引入。

## 发布、兼容与恢复

自动演化仅支持当前源码边界内的修改，不自动升级依赖、Supervisor 或执行破坏性数据迁移。

1. 记录源码基础指纹、文件摘要、前一发布与改进来源
2. 在候选目录验证类型、测试、代码健康，以及实例副本的初始化兼容性
3. 暂存候选，不热覆盖运行中的源码
4. 旧 Runtime 退出后，Supervisor 再次验证候选并核对基础指纹
5. 备份停机状态的实例与受影响源码，记录切换意图，再替换文件
6. 切换中断、验证失败或新进程启动初期崩溃时恢复旧源码
7. 保留最近两份完整备份，以及历史发布元数据和修改内容

状态格式为 `PRAGMA user_version = 1`。原有无版本状态可登记为 1；更高版本明确拒绝打开。首版自动迁移仅允许新增兼容表或字段，候选初始化不得删除旧字段或改写旧表数据。这是验收约定，不是对任意候选程序的形式化证明。

验证使用实例副本，并移除副本中的模型配置和凭证。候选测试运行在同一宿主权限下，目录隔离不等于操作系统沙箱。

普通回滚只恢复源码，不倒退用户数据，避免丢失升级后产生的新消息、成果或外部操作证据：

```bash
bun run src/index.ts --rollback
```

此命令应在现有 Supervisor 停止后使用。需要完整灾难恢复时，使用发布备份中的 `instance` 子目录恢复到新的空目录：

```bash
bun run scripts/restore-instance.ts <备份目录/instance> <新的空数据目录>
SELFCRAFT_HOME=<新的空数据目录> bun run start
```

完整快照包含私人数据和凭证，按实例本身保护。恢复时使用匹配的 Runtime 版本；完整快照不能撤销已经发生的外部操作。

## 验收边界

确定性测试覆盖接收去重、工具后中断、未知结果暂停、事项变更、等待唤醒、通知交付、旧数据导入、兼容检查、备份恢复、版本冲突及源码回退。真实模型验收使用显式 `SELFCRAFT_TEST_*` 环境变量。

跨天真实使用需要继续观察：是否正确识别持续事项、能否选好工具、是否诚实验收、通知是否适时、经验改进是否有效。实现这些机制不替代这部分验证。
