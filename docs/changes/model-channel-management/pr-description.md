# feat: 分离模型与渠道配置并支持受保护的模型删除

## 问题与结果

原 Web 表单同时承担新增模型和更新渠道：用户填写已有渠道 `dev` 再输入另一套地址和 Key，会覆盖该渠道的连接，影响已有模型；已添加模型也无法删除。

现在设置页将模型用途与渠道管理分开，渠道内提供独立的添加、编辑和删除模型入口。模型表单只提交模型能力；连接修改必须从“编辑渠道”进入。新增重名渠道或同渠道重名模型会报错，不再隐式覆盖。

## 改动

- Runtime 明确区分渠道创建、连接更新、模型新增、能力更新和模型删除，HTTP 严格限制各操作允许的字段
- 删除前校验最新的默认、反思和上下文整理引用；须先切换用途再删除，保留空渠道、凭证、其他模型和历史数据
- Web 提供影响范围说明、重名模型编辑入口、请求中防重复提交和失败后读取配置的恢复入口；首次配置支持新渠道带首模型及已有空渠道继续添加
- CLI、iOS 共用创建接口改为重名报错，并调整提示；保留各自已有的创建、选择和测试能力，已有渠道管理通过 Web 完成

## 兼容性与风险

- `POST /api/config/providers` 不再支持同名更新；旧客户端仍可创建新渠道，同名更新会被拒绝。已打开的 Web 页面需要刷新，Runtime 和 Web 产物须配套更新
- 配置仍为 v1，无数据迁移；配置与凭证仍分别原子保存，不提供跨文件事务，多客户端编辑渠道仍以后保存为准
- 未连接真实外部模型；本地连接与 smoke 通过不代表用户实际提供方可用
