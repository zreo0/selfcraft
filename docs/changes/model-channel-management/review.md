## 场景检查

| 场景 | 结果 | 依据 |
| --- | --- | --- |
| S1 添加已有渠道模型 | 满足 | `ModelForm` 仅提交模型字段；`ConfigStore.saveModel` 只写模型配置；核心测试检查连接和凭证不变 |
| S2 创建另一套连接 | 满足 | 独立 `ProviderForm` 创建渠道；本轮浏览器实际创建新空渠道，并自动进入该渠道的模型表单 |
| S3 重名渠道不覆盖 | 满足 | `addProvider` 在任何写入前检查自身属性重名；存储和 HTTP 测试验证拒绝及配置不变 |
| S4 显式编辑渠道 | 满足 | 标识只读，展示受影响模型数量；`updateProvider` 保留模型及用途，仅保存连接 |
| S5 空 Key 保留 | 满足 | `saveProviderConnection` 使用原 `credentialRef`，无新 Key 时不写凭证；表单不回显；本轮核心测试通过 |
| S6 重名模型与编辑引导 | 满足 | 服务端拒绝同渠道重名；`ModelForm` 提供编辑已有模型入口；不同渠道同模型名有测试覆盖 |
| S7 编辑模型能力 | 满足 | 模型 ID 只读，模型请求不含连接字段；更新只替换目标模型能力 |
| S8 删除未引用模型 | 满足 | `deleteModel` 仅删除目标模型映射；重新读取测试验证持久化；未调用历史、会话或记忆删除逻辑 |
| S9 引用阻止删除 | 满足 | 同步读取最新配置，检查默认、反思、整理引用；页面列明用途；存储和 HTTP 测试覆盖切换后阻止及解除引用后删除 |
| S10 唯一默认保护 | 满足 | 所有默认引用均由服务端拒绝删除；页面提示添加替代模型后切换，不自动替换或清空引用 |
| S11 保留空渠道 | 满足 | 删除最后一个未引用模型后渠道及凭证保留，持久化测试通过；本轮浏览器确认空渠道仍有添加入口 |
| S12 越界请求保护 | 满足 | HTTP 严格字段校验，拒绝模型请求中的连接字段、重复创建和混用输入；本轮 HTTP 测试通过 |
| S13 兼容与首次配置 | 满足 | 保留旧单模型、CLI 多模型创建形状；`ModelSetup` 分离新建与已有渠道恢复，只有 `configured` 才推进；CLI、iOS 提示与已批准规则一致；核心测试及实施阶段交互记录支持 |
| S14 失败与加载 | 满足 | 本轮浏览器阻断用途请求，显示错误且默认选择不变，忙碌解除；阻断刷新后显示错误，恢复网络可刷新成功；重复提交、回执丢失及陈旧删除见实施阶段实测记录 |
| S15 视觉与键盘 | 满足，部分沿用实施证据 | 本轮新渠道转模型表单后焦点位于 Dialog，Tab 进入模型 ID，Escape 返回新增入口；浅深色、移动端、减少动效及自动无障碍检查沿用实施阶段记录和截图 |
