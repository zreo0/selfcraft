# Web 模型渠道与模型管理交互优化

## 背景

Web 设置页将新增渠道、更新渠道、添加模型与编辑模型放在同一张表单中。用户想添加模型时，如果填写了已有渠道名（例如 `dev`），又填写另一套地址和 Key，保存后就会改变原渠道的连接信息，连带影响其已有模型。

已核对现有实现：`ProviderForm` 共用渠道和模型字段，保存请求进入 `ConfigStore.addProvider` 后，按渠道标识覆盖协议、地址和非空 Key，并合并模型。这是现有保存行为，而不是单纯的提示文案问题。模型列表、配置接口和配置存储目前也没有删除模型的操作。

现有配置接口还被 CLI 使用，首次配置也复用了 Web 表单。本次需要在明确操作边界的同时，保持这些入口正常工作。

## 目标

- 设置页按“渠道管理连接，渠道下面管理模型”组织；模型用途选择与渠道管理分开，保留默认模型、反思和上下文整理的用途设置
- 渠道展示名称、协议、地址与凭证状态，提供明确的“编辑渠道”和“添加模型”入口；模型行提供测试、编辑与删除操作
- 新增渠道填写名称、协议、地址与 Key；已有同名渠道时明确报错，不隐式更新
- 编辑渠道必须从对应渠道进入，渠道标识固定；保存前说明会影响该渠道下的所有模型，空 Key 保留已有凭证，凭证不回显
- 添加模型必须从所属渠道进入，固定渠道，只填写模型 ID、能力和上下文参数，不要求填写或修改渠道地址和 Key
- 编辑模型只修改能力与上下文参数，不改变所属渠道、模型 ID 或渠道连接；同渠道新增同名模型时报错，并引导进入编辑
- 后端明确区分创建渠道、更新渠道、添加模型、更新模型与删除模型；添加或编辑模型的请求不能改变渠道协议、地址或凭证，不能仅依赖页面限制
- 支持删除未被用途配置引用的模型，删除前确认目标；保留所属渠道、其他模型及渠道凭证，不删除历史会话或记忆
- 默认模型、反思或上下文整理引用的模型不能直接删除；展示具体用途，引导先切换模型，或将反思、上下文整理恢复为“跟随默认”后再删除
- 唯一的默认模型必须先添加替代模型并完成切换，避免删除后实例无法工作；不自动选择替代模型，不静默清除用途引用
- 保持已有配置可读取、首次配置可完成；共享创建接口一并收紧为重名报错，CLI 和 iOS 保留新渠道创建及各自已有的模型选择、测试能力，并做必要的提示适配；已有渠道的编辑与添加模型统一从 Web 完成

## 不做什么

- 不扩展渠道重命名、模型 ID 重命名、模型跨渠道搬迁或自动发现模型
- 不新增渠道删除、批量删除或自动清理空渠道
- 不改造设置页中与本次需求无关的网络搜索、时区和重新初始化功能
- 不重构 Agent Loop、Supervisor 或会话与记忆管理

## 场景

| 编号 | 场景 | 期望结果 |
| --- | --- | --- |
| S1 | 已有 `dev` 渠道，用户想在该渠道增加模型 | 从 `dev` 的“添加模型”进入，只填模型信息；保存后旧模型、渠道协议、地址和 Key 均保持不变 |
| S2 | 用户想使用另一套地址和 Key | 从“新增渠道”创建独立渠道，不改变 `dev` 及其已有模型 |
| S3 | 新增渠道时填写已有名称 `dev` | 明确报错并提示已有渠道，不覆盖任何配置或凭证 |
| S4 | 用户主动修改 `dev` 的地址、协议或 Key | 从“编辑渠道”进入，渠道标识不可修改；保存前可见影响范围，保存后仅更新该渠道的连接信息，保留模型及用途选择 |
| S5 | 编辑渠道时不填写新 Key | 保留已有凭证；页面只显示凭证状态，不读取或展示原 Key |
| S6 | 在同一渠道新增已存在的模型 ID | 明确报错并引导编辑已有模型，不覆盖原模型参数；不同渠道允许使用相同模型 ID |
| S7 | 用户编辑已有模型的能力或上下文参数 | 只更新目标模型参数，不修改模型 ID、渠道连接、其他模型或用途选择 |
| S8 | 删除没有被默认、反思或上下文整理引用的模型 | 确认后删除目标模型；刷新页面后仍保持删除结果，渠道、凭证、其他模型、历史会话和记忆保留 |
| S9 | 删除被默认、反思或上下文整理引用的模型 | 展示具体引用用途并阻止删除；用户先切换用途或恢复适用的“跟随默认”后，才能删除；后端同样校验引用 |
| S10 | 删除实例中唯一的默认模型 | 阻止删除并说明需要先添加替代模型、切换默认选择，不使实例进入不可用状态 |
| S11 | 某渠道的最后一个模型未被用途引用并被删除 | 保留空渠道及其凭证，展示无模型状态，仍可从该渠道添加模型 |
| S12 | 绕过页面直接提交重名创建或越界的模型修改请求 | 后端拒绝冲突或越界操作，不隐式覆盖渠道、凭证或已有模型 |
| S13 | 读取已有配置、首次配置或通过 CLI、iOS 创建新渠道和选择模型 | 已有数据保留，各入口首次配置与新渠道创建可完成；旧接口重名新增也报错，提示通过 Web 管理已有渠道，不再提供隐式更新 |
| S14 | 保存或删除期间发生请求失败 | 显示明确错误，页面不误报成功；提供加载状态并防止重复提交 |
| S15 | 在浅色、深色、键盘操作和移动端使用管理页面 | 操作入口、焦点、错误、空状态及加载状态清晰可用，层级关系不会因布局变化而混淆 |

验收以复现 `dev` 误覆盖场景、验证新增与编辑隔离、删除引用保护和持久化结果为核心；对配置写入与引用约束补充必要测试，并按项目要求执行适用检查。具体实现与验证步骤在 `oi-plan` 阶段确定。
