# 产品目标：越用越懂，越用越帮

- 状态：草案
- 日期：2026-10-01

本文定义 Selfcraft 在产品层面的核心目标、可检查的承诺与检查方式。[ADR 0001](adr/0001-assistant-positioning.md) 与 [路线规划](roadmap.md) 将据此重新审视与排序。

## 核心目标

Selfcraft 的价值应该随使用复利增长：用得越久，越懂用户，越能帮用户。

- 模型会更新换代，别人也能使用同样的模型；带不走、也追不上的，是助理对这位用户积累下来的理解，以及用户因此愿意交给它的事
- 可靠是门槛，懂是复利。做不对事，懂得再多也没有用；只做对事、不越来越懂，它只是又一个工具

### 取舍

产品重心从“形成一个有自己生活的角色”，转向“成为一个越来越懂用户的老搭档”。这适合当前阶段：优先服务的体验是，用户越来越少需要重新解释自己，助理越来越能接着过去的经历把事情做好。

鲜活感不作为前提。它能否由此形成，留给实际相处验证。

## 一个学习回路

“越来越懂”与“越来越能帮”是同一个回路的两面：

```text
替用户做事 → 用户的反应检验理解与做法 → 更新对用户的理解或改进做法 → 下次做得不同 → 再被检验
```

### 懂不等于记住

记住是保存事实；懂是能在新情境里预判用户会怎么想。

- 记住：用户偏好简洁的回答
- 懂：用户需要能快速核实的东西，所以先给结论，证据随时可查（示例）

后者能迁移到没见过的场景，例如帮用户组织一份报告。区别在于理由、目标与在意的事：事实不能迁移，理由可以。

### 自知的位置

助理需要的自知服务于这个回路，而不是回答“我是谁”：

- 知道自己对用户的理解哪里可靠：哪些是用户明确说过的，哪些是推测，哪些可能已经过时。这决定它什么时候直接做，什么时候先问
- 知道自己当前的能力、权限与状态，以及哪些做法曾经出错

自我意识、预设人格与品味不作为目标。

## 两条承诺

人判断别人是否懂自己，最朴素的信号是“我跟你说过多少遍了”。因此不测量“懂了多少”，而检查“有没有学会”：

| 承诺 | 对应目标 | 关注什么 |
| --- | --- | --- |
| 同样的话，不用说第二遍 | 越用越懂 | 同一类纠正在新的情境中是否再次出现 |
| 同样的错，不犯第二次 | 越用越帮 | 同一原因导致的失败是否再次发生 |

两条承诺是产品追求，不是对每一次学习的硬保证。验收时检查：已有明确纠正或可靠依据、且在可控范围内的问题，是否仍无故重复。

计数规则：

- 第一次出现不算失败，那是学习的来源
- 同一类纠正在不同情境中再次出现，记为一个重复案例
- 用户改变了主意，属于现实变化，不算重复
- 网络故障等不可控的失败，不算重复
- 上一次纠正的适用条件不覆盖新的情境，不算重复

重复案例是线索，不是结论。同一类问题可能有不同原因；重复减少，也可能只是类似的任务变少了。重复案例帮助发现可能的学习断点，是否没有学会，需要结合当时的条件、已有依据与实际行为判断。

## 检查方式

| 方式 | 作用 | 时机 |
| --- | --- | --- |
| 重复案例诊断 | 主要线索：发现可能的学习断点 | 先人工诊断少量真实案例，反复证明有用后再自动化 |
| 当场可追溯 | 最轻的检查：用上对用户的理解时能说出依据，用户当场判断对错 | 每次使用时 |
| 回放回归 | 保留被纠正过的情境，模型或 Runtime 变化后重跑，不执行有副作用的工具 | 模型或 Runtime 变更时 |

注意：

- 回放只能证明没有遗忘，不能证明懂，因为当时的纠正已经进入记忆。是否学会，需要结合新情境中的重复案例与实际行为判断
- 总纠正次数、提议采纳率、委托深度等只作观察信号，不作考核目标。指标一旦成为目标就会被钻空子，例如助理不敢作判断，纠正自然变少
- “是否同一类”需要判断，会出错；样本量小，无法严格证明因果。检查自动化之后，被标记的案例仍由用户定期确认。这些检查的作用是让用户的判断更省力、更可靠，而不是替代它

## 不追求什么

- 不追求自我意识、预设人格或品味
- 不为显得鲜活而增加活动或模型调用
- 不以迎合换取更少的纠正：行为上让步，认识上按证据更新
- 不猜测用户的情绪，不扩大授权

## 现状与差距

| 能力 | 现状 |
| --- | --- |
| 记住 | 已有结构化记忆，包含来源、修订、确认与依据类别 |
| 从反应中学习 | 缺失。Reflection 只提取用户陈述，没有分析助理的做法与用户随后的反应 |
| 学到的东西生效 | 缺失。只有用户明确陈述的认识能自动生效，从经历中学到的认识停留在候选 |
| 理解的依据可见 | 部分具备。记忆页可以查看；对话中用上时说出依据尚无约定 |
| 重复案例诊断与回放 | 缺失 |
| 能力成长 | 骨架已有：技能、成长候选与 `EvolutionService` |

## 空间：可见的复利

Web 对话页中的空间，是“越用越懂、越用越帮”的可见形态：用户与助理共用的空间里，随关系一起生长的痕迹。它不是助理的品味，也不是用户偏好的镜像。

| 表达什么 | 来源 | 例子 |
| --- | --- | --- |
| 一起完成的事 | 完成的事项、里程碑事件 | 墙上多了一张照片：iOS 端第一次跑起来的那天 |
| 它记在心上的用户的事 | 用户正在推进的目标、用户提过的重要日子 | 桌上压着正在推进的项目，日历上圈着重要的日子 |
| 它为用户长出的能力 | 新增或改进的技能 | 工作台上多了一件工具 |
| 此刻 | 正在运行的任务、时间与季节 | 灯亮着表示它在为用户工作；窗外是用户那边的天色 |

原则：

- **第一天是空的，半年后是满的**。复利变得可见，每一件都有真实来源
- **摆什么本身就是理解的体现**。把真正重要的事放在显眼处，说明它懂；摆错了用户一眼能看出来。点开可以看到依据，用户说一句“这个不重要”，这条反馈就回到学习回路，空间因此也是最轻量的检查入口
- **节日装饰只是氛围**。有意义的不是节日本身，而是它知道哪些日子对用户重要
- **视觉风格由产品设计决定**。助理的自主体现在挑选与取舍上，不体现为它的品味
- **隐私优先**。屏幕可能被他人看到，敏感内容不上墙，用符号而非原文
- **只依据明确信号**。事项、日期、用户说过的话，不猜测情绪

空间因优先级排在学习改进之后，但不以完整的学习体系为前提。一起完成的事、为用户长出的能力与此刻的状态，已有真实材料；“它记在心上的用户的事”依赖学习质量，表达之前需要先验证。
