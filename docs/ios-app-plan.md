# iPhone App 设计与实施方案

状态：已实现 iOS 工程、共享接入协议与语音闭环，完成模拟器和测试容器的首轮联调；真机与 APNs 仍有未完成项，见 [验收记录](ios-validation.md)

## 目标与边界

- iPhone App 是与 Web、CLI 并列的正式入口，无需另建硬件测试 App
- Runtime 持有身份、记忆、持续对话、事项和 Agent Loop，App 不复制这些职责
- 先通过地址和凭证连接本地 Runtime，未来公网连接沿用同一协议
- 首版面向 iPhone，Android 和真实 BLE 硬件接入后续开展
- 保留 APNs 完整设计；用户未来开通 Apple Developer Program 后补做远程推送真机验收
- 既有产品与架构约束参见 [PRODUCT.md](../PRODUCT.md)、[运行与升级约定](first-version-contract.md)

## 已确认的交互决策

### 语音输入与消息

- 按住录音，正常松手后上传、转写并自动提交对话；上滑取消
- 单条录音最多 2 分钟；达到上限后停止并保留，用户确认后才发送
- 来电、锁屏、切换 App 导致录音中断时，停止并保留草稿，不自动发送
- 草稿可以试听、发送或删除；不能在恢复前台后擅自提交中断内容
- 用户语音消息上方显示可播放的语音条、时长和进度，下方直接展示转录文本
- 原始录音默认不播放，点击后播放，支持暂停；消息显示上传、转写和失败状态
- 转写失败保留录音并提供重试，不向 Agent 提交空文本
- Runtime 保存原始录音作为消息附件，允许单独删除音频并保留转录文字
- 音频保存不等于写入长期记忆；不把音频删除描述为删除所有历史证据
- 助手仍输出文字，用户点击朗读时使用 iOS 系统语音；不自动朗读

### 离线与恢复

- App 保存带稳定提交标识和采集时间的待发送内容
- 原本已由用户发起发送、但 Runtime 尚未接收的内容，断线后在采集时间起 5 分钟内允许自动补发
- 超过 5 分钟的未接收内容必须确认发送或丢弃；中断草稿与达到录音上限的草稿不进入自动补发
- 回执不明时先核实同一标识的处理状态；不能生成新标识重复执行
- 已持久接收的工作由 Runtime 继续执行，App 离线、退出或切换连接不取消工作
- 本地待上传音频在 Runtime 确认持久保存后才可清理；服务端音频与转写处理状态须可恢复

### 多连接与通知跳转

- 主界面始终只展示当前连接实例的内容，不把多 Runtime 作为日常产品概念
- 在设置的开发选项中提供连接管理，支持保存、编辑、删除和切换连接
- 每个实例独立保存凭证、缓存、草稿、待发送内容和事件游标
- 实例身份使用服务端稳定标识，不能以 URL 作为唯一身份；同一实例从本地迁到公网不应被视为全新助理
- 切换时隔离旧请求与迟到响应；未接收内容留在原实例，不自动转投新实例
- 点击来自其他已保存实例的通知时，先提示确认切换，再打开对应内容；拒绝后保持当前实例
- 切换保留原实例草稿；无法连接、凭证失效或目标已删除时呈现可恢复状态

## App 页面与工程方案

以下是实施采用的工作方案，可在原型与代码验证中调整，不再为可逆的内部选择单独增加产品问答。

| 页面 | 首版职责 |
| --- | --- |
| 连接与首次认识 | 地址、凭证、连接诊断；根据 Runtime 初始化状态完成引导 |
| 对话 | 持续历史、文本与图片、语音条与转录、流式输出、Markdown、引用、工具活动、停止当前回复 |
| 事项 | 查看持续事项、进展、等待条件、结果；补充要求与取消遵循现有 Work 约束 |
| 记忆 | 查看、确认、纠正、忘记、常驻状态、来源与历史，沿用现有记忆语义 |
| 设置 | 模型与转写配置、时区、外观、权限、连接诊断及开发连接管理 |
| 通知入口 | 通知列表、未读状态、目标跳转；不要求独立增加一个 Tab |

- 导航采用对话主页面，不保留底部 Tab；左上云朵打开近况与功能面板，事项、记忆、设置在其中展开，右上保留通知和未读提示
- 文字和按住说话共用底部输入区，通过显式按钮切换；草稿与对话滚动位置保留，录音中打开其他页面先保存为待确认内容
- 工程放在仓库 `ios/`，采用原生 SwiftUI、Observation 和结构化并发；暂以 iOS 18 为最低目标，在工程建立时核实所用 API 的可用性
- 按实际页面与服务划分职责，不要求每个 View 都有 ViewModel，不引入没有调用方的通用仓库层
- Runtime 数据是事实来源；App 本地只保存连接偏好、凭证引用、草稿、待发送状态和必要的只读缓存
- 凭证保存在 Keychain，供应商密钥只保存在 Runtime 的受限凭证文件，不随普通配置读取返回
- 视觉沿用 [DESIGN.md](../DESIGN.md) 的澄蓝、墨白、浅色与深色语义，保持连续对话、克制层级和留白
- 使用原生导航、系统正文排版、可访问性标签与动态字号，覆盖加载、空、错误、离线和权限被拒绝的状态
- 按住录音之外需要提供可访问性等价操作，不能让操作依赖手势精度

## Runtime 接口补齐

截至方案整理时，现有服务已有对话提交与事件流、图片附件、配置、记忆、Job、Task 和基础通知接口；尚未形成完整移动端协议。

| 能力 | 实现要求 |
| --- | --- |
| 连接身份 | 握手返回稳定实例标识、协议版本与能力；区别未初始化、无权限、版本不兼容和不可达 |
| 客户端鉴权 | 地址配合可撤销、可轮换的凭证；覆盖读取、变更、附件和事件流，不能仅依赖 Origin 校验 |
| 客户端兼容 | 同步适配 Web、CLI 的接入流程，保持各入口面对同一初始化状态与持久数据 |
| 持久接收 | 稳定提交 ID、处理状态查询、去重、断线重连与事件补读；游标失效时重新拉取快照 |
| 音频附件 | 校验文件大小、格式和时长，经 PathGuard 保存；提供受鉴权保护的读取与删除 |
| 转写任务 | 区分音频已保存、转写中、转写失败、文本已提交；重试转写不重复创建 Agent 执行 |
| 事项接口 | 面向 Work 的查看和受约束操作，不能把 Job 当作持续事项，也不能绕过版本及授权规则直接改记录 |
| 通知 | 持久通知标识、逐条已读、目标定位、设备注册与撤销、投递状态；推送不是通知事实来源 |

接口字段、端点、状态迁移和持久化兼容方案应在对应功能编码前定义，并通过契约测试验证。已有可复用存储与去重机制优先复用，不另建第二套 Agent 队列。

本地开发可采用受限制的 HTTP 调试配置，正式远程连接使用 HTTPS。真机连接使用可达的局域网地址；公网 IP 本身不能替代 TLS、鉴权与网络可达配置。不得为了手机联调默认将未鉴权服务暴露到公网。

## 转写服务

- Runtime 使用 AI SDK `transcribe()` 作为统一调用入口
- 首个供应商为硅基流动，模型为 `FunAudioLLM/SenseVoiceSmall`，地址为 `https://api.siliconflow.cn/v1`
- 语音识别模型独立于对话模型配置，可复用渠道凭证；不能套用语言模型的上下文窗口等无关必填项
- 当前依赖中 `@ai-sdk/openai-compatible` 没有转写入口，使用 `@ai-sdk/openai` 的转写模型配合自定义地址
- 首版请求只传供应商支持的字段，不默认添加 OpenAI 专属选项
- 供应商只保证返回文本时，不能要求存在分段、语言或时长；录音时长由实际音频信息补足
- 手机与硬件共享 Runtime 转写流程；本方案不承诺实时流式识别
- 适配层仍需处理音频格式限制、超时、限流与供应商错误差异，避免 SDK 与业务重试叠加

已验证：项目安装的 `ai@7.0.31`、`@ai-sdk/openai@4.0.16` 在本地模拟请求中生成 `POST /audio/transcriptions`，表单为 `model`、`file`，能够解析仅含 `text` 的响应。

2026-09-29 真实接口验证：约 9.39 秒的合成中文 PCM WAV 经硅基流动识别成功，单次耗时约 40.3 秒，重复请求读取已持久缓存，App 展示语音条和转录并可播放原件。出现“请只回复”被识别为“请知回复”的误字。这只是一次联调数据，不能据此保证识别质量或延迟。

未验证：iPhone 真机麦克风在各音频路由下的编码、噪声环境识别质量、长期延迟分布及费用。

参考：[AI SDK Transcription](https://ai-sdk.dev/docs/ai-sdk-core/transcription)、[硅基流动转写接口](https://api-docs.siliconflow.cn/docs/api/audio-transcriptions-post)。

## APNs 与暂缓验收

- Runtime 持久保存通知，App 前台或重新连接时同步；通知列表与已读功能属于首阶段验收
- APNs 投递采用持久通知标识和实例、目标标识关联；通知正文默认克制，避免携带完整私人对话
- 设计包括授权状态、设备 token 更新、环境区分、无效注册清理及凭证管理
- 本地开发阶段可以验证通知路由、注册协议和投递逻辑，不把模拟投递当作真实推送验收
- 用户暂未开通付费开发者会员，真实 APNs、App 不在前台时的远程通知展示与点击恢复标记为待验收
- 无 APNs 配置不阻断其余 App 功能；开通后补齐签名与能力配置，并完成真机验收
- 不以后台长期保持事件流连接替代推送，不承诺任意系统状态下的通知必达

## 实施顺序与验收

1. **连接协议与原生基础工程**：鉴权、实例身份、初始化状态、单个活动连接、多连接开发入口；验证错误凭证、地址变更和跨实例数据隔离
2. **完整文本入口**：引导、历史、输入、流式状态、图片与恢复；验证与 Web/CLI 共享状态、持久接收去重和退出后任务继续
3. **手机语音闭环**：录音、音频存储、转写、语音消息展示和原音播放；验证两分钟上限、中断草稿、转写失败、离线五分钟边界及恢复后不重复执行
4. **事项、记忆、设置与通知**：按现有领域规则补齐接口和页面；验证事项版本约束、记忆操作、通知跳转与切换确认
5. **完整真机回归**：权限、网络切换、前后台恢复、浅深主题、动态字号及本地化；记录真实转写效果与延迟
6. **条件具备后的补验**：开通开发者会员后验收 APNs；硬件到货后接入 BLE 音频来源，不重新开发另一套业务 App

核心自动化验证覆盖实例隔离、提交去重、录音状态迁移、转写重试和通知路由，不为简单视觉布局添加镜像测试。Runtime 代码变更遵循仓库要求执行类型检查、测试、doctor 与相关 smoke；涉及 Agent 执行时使用显式测试凭证完成真实模型验收。

## 当前结论

工程与运行步骤见 [iOS README](../ios/README.md)。本轮实现了连接鉴权、持续对话、语音、事项、记忆、设置与通知列表；通过真实容器验证了 Web Cookie、iOS Bearer、CLI 订阅共享会话与重复提交去重。

APNs 当前只有权限和通知定位入口，设备 token 注册、服务端 APNs 投递、签名能力尚待实现；保留以上设计，未来开通能力后补齐并验收。真机录音、中断、网络变化、可访问性及完整发布准备也不能标记为已验收。
